## 写在前面

作为一个连 `Git` 和 `Node.js` 是什么都不知道的纯小白，我花了整整一天的时间，终于把个人博客部署到了 Cloudflare 上。

这一路踩过的坑，我觉得有必要记录下来。如果你也遇到了 Cloudflare 部署失败的问题，这篇文章或许能帮你省下几个小时。

---

## 故事的开始

跟着B站UP主番茄煮理人的教程，我一步步完成了：
- Fork 仓库
- 本地安装环境（Node、pnpm、Git）
- 克隆代码到本地
- 修改配置
- 推送到 GitHub

一切看起来都很顺利，直到我打开了 Cloudflare 控制台……

---

## 第一次尝试：选错了入口

教程上说要在 Cloudflare 创建 **Pages** 项目，但是我在控制台里找了一圈，直接点进了 **Workers & Pages** 入口，然后选择了 **"创建 Worker"**。

结果就是：**访问网址一直是空白页，或者提示"响应时间太长"**。

我反复检查了构建命令、输出目录、环境变量，甚至看了好几遍构建日志，明明都是 `Success`，但网页就是打不开。

### 当时的错误表现：
- 访问 `https://cxz-b9n.pages.dev/` 显示 **"响应时间太长"**
- 构建日志全绿，没有任何报错
- 重试了 N 次，依然失败

---

## 关键发现：Pages 不是 Worker！

后来我才发现，Cloudflare 的 **Worker** 和 **Pages** 是两个完全不同的产品：

| 功能 | Pages | Worker |
|------|-------|--------|
| 用途 | 托管静态网站 | 运行服务端代码 |
| 部署方式 | 自动从 Git 拉取构建 | 需要编写 Worker 脚本 |
| 适用场景 | 博客、文档站、静态页面 | API 服务、动态功能 |

我的博客是 Astro 生成的静态 HTML，**应该用 Pages，而不是 Worker**。

---

## 正确的做法
![正确打开Pages的截图](./Pages.avif)

在 Cloudflare 控制台的 **Workers & Pages** 页面，不要直接点"创建 Worker"，而是：

1. 点击 **"需要使用旧版Pages的工作流程吗？ 继续阅读"**
2. 切换到 **Pages** 选项卡（不是 Worker！）
3. 连接 GitHub，选择你的仓库
4. 填写构建设置：
   - **构建命令**：`pnpm build`
   - **输出目录**：`dist`

部署完成后，访问的是 `cxz-b9n.pages.dev`，而不是 `xxcxz-b9n.workers.dev`。

---

## 血的教训

**如果你也遇到 Cloudflare 部署后无法访问，先检查你的项目类型是 Pages 还是 Worker。**

Pages 的域名是 `*.pages.dev`，Worker 的域名是 `*.workers.dev`。如果你选错了入口，即使构建日志全绿，网站也跑不起来。
